### ШАГ 7 — Решение проблемы Tailscale / веб-версия

**Роль:** `R-SYSTEMS-ENGINEER` + `R-SECURITY-SPECIALIST`
**Скиллы/инструменты:** `Serena`, `Bash`, `WebSearch` (альтернативы Tailscale)

> **Проблема:** Веб-версия через Tailscale имеет постоянные обрывы. Mobile web app на iPhone не работает. Нужно решение которое работает на 100%.

#### 7.1 Диагностика текущего состояния
- 7.1.1 Как сейчас работает веб-версия (ws_bridge.py → Tailscale → браузер?)
- 7.1.2 Какие порты, протоколы, SSL
- 7.1.3 Почему обрывы (Tailscale MagicDNS? NAT traversal? Sleep?)
- 7.1.4 Почему iPhone не работает (Safari WebSocket? SSL cert? PWA manifest?)

#### 7.2 Варианты решений
- 7.2.1 **Cloudflare Tunnel** (бесплатно):
  - cloudflared tunnel → публичный URL с SSL
  - Стабильнее Tailscale для веб
  - Работает с iPhone Safari
  - Безопасно: tunnel, не открытый порт
- 7.2.2 **ngrok** (условно бесплатно):
  - Простой, стабильный
  - Минус: URL меняется на бесплатном плане
- 7.2.3 **Reverse SSH tunnel** (нужен VPS):
  - SSH к VPS → reverse port forward
  - Стабильно, но нужен VPS
- 7.2.4 **Railway deploy** (веб-часть на Railway):
  - Бот локально, веб на Railway
  - Но бот должен мониторить ЛОКАЛЬНЫЕ сессии — нужен bridge
- 7.2.5 **Локальная сеть (.local):**
  - Минус: не работает вне дома

#### 7.3 Выбор и реализация
- 7.3.1 Выбрать решение (рекомендация: Cloudflare Tunnel - точно подверья что не поймаем тех же ошибок)
- 7.3.2 Настроить
- 7.3.3 Протестировать:
  - Desktop браузер: стабильность 30 минут без обрывов
  - iPhone Safari, Chrome: WebSocket работает, PWA работает
  - Android 
  - Автореконнект при потере связи
- 7.3.4 Автозапуск: tunnel стартует вместе с ботом

#### 7.4 Результат
- 7.4.1 Веб-версия работает стабильно без Tailscale
- 7.4.2 iPhone работает
- 7.4.3 Безопасно (нет открытых портов)
- 7.4.4 Документация: как настроено, как перезапустить
