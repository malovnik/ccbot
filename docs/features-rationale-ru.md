# CCBot: 20 улучшений — обоснование каждой фичи

> Результат 20-итерационного цикла непрерывного улучшения через Ralph Loop.
> Каждая фича прошла: исследование, валидацию через Sequential Thinking, реализацию, semgrep аудит.

---

## 1. Graceful Shutdown с уведомлениями

**Проблема:** При рестарте бота (Railway redeploy, systemd restart) пользователь видел тишину. Claude продолжал работать, но сообщения переставали приходить. Пользователь не понимал: бот завис? Claude сломался? Интернет?

**Решение:** При SIGTERM бот отправляет "Бот перезапускается. Ваши сессии сохранены." во все активные топики. При следующем старте — "Бот снова в сети." Маркер чистого завершения (`~/.ccbot/.shutdown_clean`) различает planned restart и crash.

**Почему это важно:** Production-бот должен коммуницировать своё состояние. Тишина при рестарте — нарушение контракта с пользователем.

---

## 2. /health — диагностика бота

**Проблема:** Единственный способ узнать состояние бота — SSH на сервер и смотреть логи. Telegram-мост теряет смысл если для проверки здоровья нужен прямой доступ.

**Решение:** Команда `/health` показывает: аптайм, количество сессий, статус tmux, монитор, память, версию Python. Всё в одном сообщении.

**Почему это важно:** Observability — обязательный атрибут production-сервиса. Без `/health` бот — чёрный ящик.

---

## 3. Пересылка исправленных сообщений

**Проблема:** Пользователь отправил сообщение с опечаткой. В Telegram можно отредактировать. Но бот игнорировал edit — Claude получал только оригинал.

**Решение:** Edited messages пересылаются с префиксом "(Исправление)". Claude понимает что это замена предыдущего ввода.

**Почему это важно:** Ежедневная боль. Без этого приходится отправлять новое сообщение с пояснением "я имел в виду...", загрязняя контекст.

---

## 4. Загрузка документов

**Проблема:** Пользователь не мог отправить файл (код, конфиг, PDF) в Claude через Telegram. Документы падали в "Не поддерживается".

**Решение:** Полноценный handler: скачивает файл → сохраняет в `~/.ccbot/documents/` → отправляет путь Claude. Extension allowlist (50+ форматов), blocklist чувствительных имён (.env, credentials), лимит 20MB.

**Почему это важно:** "Посмотри этот файл" — одна из самых частых операций. Без document handler Telegram-мост неполноценен.

---

## 5. Idle Detection — напоминание при бездействии

**Проблема:** Claude закончил работу, отправил ответ. Пользователь в другом чате, не заметил. Claude сидит и ждёт. Минуты, иногда часы.

**Решение:** Если Claude ответил текстом, а пользователь молчит 2 минуты — одноразовое напоминание "Claude ожидает ваш ответ." Сбрасывается при новом сообщении. Настраивается через `CCBOT_IDLE_REMINDER_SECONDS` (0 = выкл).

**Почему это важно:** Аналог push-уведомления при завершении задачи. Claude-Code-Remote решает это через мобильное приложение. Мы решаем это внутри Telegram — где пользователь и так находится.

---

## 6. Группировка быстрых сообщений (Input Batching)

**Проблема:** Пользователь печатает быстро, отправляет 3 сообщения за 2 секунды. Claude получает 3 отдельных промпта → 3 отдельных ответа → хаос в контексте.

**Решение:** Debounce 1.5 секунды. Быстрые сообщения накапливаются в буфере и отправляются одним промптом через `\n`. Bash-команды (`!`) и interactive UI обходят батчинг.

**Почему это важно:** Паттерн из Slack/Discord ботов. Разница между "фрагментированный контекст" и "связный промпт" — это разница между потраченным и сэкономленным временем.

---

## 7. Rich Progress Status — что делает Claude

**Проблема:** В clean output mode пользователь видит "Работаю..." и ждёт. Минуту, пять, десять. Не знает: Claude читает файл? Запускает тесты? Завис?

**Решение:** Вместо "Работаю..." — конкретное действие: "Читаю src/auth.py", "Редактирую config.ts", "npm test", "Думаю...". Обновляется in-place через edit_message_text. Покрывает Read, Write, Edit, Bash, Grep, Glob, Agent, MCP tools, thinking.

**Почему это важно:** Это мост между TUI status bar Claude Code и Telegram. Прозрачность вместо чёрного ящика. Пользователь может решить: ждать или прервать.

---

## 8. /summary — обзор сессии

**Проблема:** Пользователь возвращается к топику через час. Не помнит контекст. /history показывает сырые сообщения — нужно скроллить и вчитываться.

**Решение:** `/summary` извлекает структурированный дайджест из JSONL транскрипта: последние 3 ответа Claude, список файлов (Read/Write/Edit), выполненные команды (Bash). Не AI-суммаризация, а data extraction — мгновенно и надёжно.

**Почему это важно:** При 5-10 активных сессиях recall контекста — критический bottleneck. /summary экономит минуты на каждом переключении.

---

## 9. Auto-restart при крашах Claude

**Проблема:** Claude Code иногда падает (OOM, network, TUI bug). Текущее поведение: 5 секунд grace → kill window → "Сессия завершена". Пользователь должен вручную пересоздавать.

**Решение:** При обнаружении exit: вместо kill → `claude --resume <session_id>` в том же окне. Макс 2 попытки с 60-секундным cooldown. После 2 неудач — стандартный kill. Пользователь видит "Сессия перезапущена автоматически."

**Почему это важно:** Трансформирует crash из "сессия потеряна" в "прозрачное восстановление". Ключевое свойство tmux: shell переживает exit process'а — мы просто вводим новую команду.

---

## 10. Нативные /kill и /restart

**Проблема:** `/kill` был в меню бота, но НЕ имел обработчика. Текст "/kill" пересылался в Claude Code, который не знает такой команды. `/restart` не существовал вообще — для "начать заново" нужно 5 шагов.

**Решение:** `/kill` — убивает tmux окно, отвязывает топик, удаляет форум-топик. `/restart` — убивает текущую сессию и создаёт новую в ТОЙ ЖЕ директории и ТОМ ЖЕ топике. Один шаг вместо пяти.

**Почему это важно:** Ghost menu commands (кнопка есть, функции нет) — плохой UX. /restart решает ежедневную боль "сессия застряла, хочу начать чисто".

---

## 11. /sessions — глобальный dashboard

**Проблема:** С 5+ топиками найти нужный — скроллить список в Telegram. Нет способа увидеть все сессии с их состоянием одним взглядом.

**Решение:** `/sessions` показывает все привязки: имя окна, директорию, статус (работает/остановлен). Работает из любого топика — глобальный обзор.

**Почему это важно:** "Control center" для multi-session workflows. Без него пользователь вслепую ищет нужный топик.

## 12. Контекст пересланных сообщений

**Проблема:** Пользователь пересылает сообщение из другого чата в Claude для анализа. Claude получает просто текст — не знает что это чужое сообщение, кто написал, откуда.

**Решение:** Автоматический префикс "(Переслано от Имя)" для всех типов: текст, фото, документы, голос. Поддержка всех forward_origin типов: пользователи, чаты, каналы.

**Почему это важно:** Пересылка — естественный способ дать Claude контекст из другого разговора. Без метаданных Claude не различает "мой вопрос" от "вопрос коллеги, помоги ответить".

## 13. Диагностика при старте

**Проблема:** Если tmux сервер мёртв, бот стартует нормально. Ошибка проявляется только когда пользователь пытается создать сессию: "Failed to create window" — без объяснения почему.

**Решение:** При старте проверяется: tmux доступен, state файлы читаемы, директория записываема, Deepgram API key (опционально). Результат логируется и отправляется пользователям.

**Почему это важно:** Fail-fast принцип. Проблема инфраструктуры должна обнаруживаться при СТАРТЕ, а не при первом действии пользователя. Экономит часы отладки.

## 14. Smart Excerpt для длинных ответов

**Проблема:** Claude написал развёрнутый ответ на 8000 символов. Telegram разбивает на [1/3], [2/3], [3/3] — три сообщения спамят чат. На мобильном — ещё хуже.

**Решение:** Ответы > 6000 символов отправляются как: превью (500 символов) + полный текст в .md файле-вложении. Один текст + один файл вместо 3+ сообщений. In-memory `InputFile` — без записи на диск.

**Почему это важно:** Паттерн email-клиента: показать суть, полный текст по клику. Радикально улучшает читаемость на мобильном.

---

## 15. Авто-именование топиков

**Проблема:** Пользователь создаёт топик "New topic", отправляет сообщение. Через 10 таких топиков — список из "New topic", "New topic 2", "New topic 3"... Невозможно найти нужный.

**Решение:** При первом содержательном сообщении (>10 символов, не "привет") — автоматическое переименование топика по первым 30 символам текста. Также синхронизирует имя tmux окна.

**Почему это важно:** Паттерн ChatGPT — auto-naming conversations. Топики становятся самодокументирующимися. С одного взгляда видно: "Fix auth in login.py", "Review PR #42", "Напиши тесты для API".

## 16. Автоматическая очистка файлов

**Проблема:** Каждое фото/документ сохраняется навсегда в `~/.ccbot/images/` и `~/.ccbot/documents/`. На Railway с 10GB диском — бомба замедленного действия.

**Решение:** Фоновая задача каждые 6 часов удаляет файлы старше 7 дней. Настраивается через `CCBOT_FILE_RETENTION_DAYS` (0 = хранить вечно).

**Почему это важно:** Один из тех случаев где "всё работает" до момента когда диск заканчивается. Retention policy — стандарт для production-сервисов.

## 17. Контекст цитирования

**Проблема:** Пользователь отвечает на конкретное сообщение Claude (quote-reply в Telegram). Claude получает только новый текст — не знает на ЧТО пользователь отвечает.

**Решение:** Цитируемый текст извлекается и добавляется как контекст: "(В ответ на: {цитата})\n{сообщение}". Работает для всех типов ввода. Цитата ограничена 200 символами.

**Почему это важно:** Reply-quote — основной механизм ссылки на конкретное сообщение в Telegram. Без этого контекста Claude теряет нить разговора при множественных ответах.

## 18. Комплексный тест-suite

**Проблема:** 17 новых фич, 0 новых тестов. Любое изменение в будущем может сломать новый функционал без обнаружения.

**Решение:** 31 тест для критических pure-функций: `_format_tool_status` (14 кейсов — все типы инструментов, truncation, MCP, fallback), config (11 кейсов — все новые поля), document constants (3 кейса), autoname patterns (3 кейса).

**Почему это важно:** Тесты — это не документация, это код. Они ловят регрессии. 268 тестов (было 237) — все проходят за 0.3 секунды.

---

## 19. Глобальный обработчик ошибок

**Проблема:** Без `add_error_handler` любое необработанное исключение в handler'е → тишина. Пользователь нажимает кнопку, отправляет сообщение — ничего не происходит. Разработчик узнаёт только из логов.

**Решение:** Глобальный error handler: пользователь получает "Произошла ошибка. Попробуй ещё раз." (rate-limited: 1 за 10 сек). Разработчик получает traceback в Telegram DM. Ловит ВСЕ необработанные исключения из ВСЕХ handler'ов.

**Почему это важно:** Это safety net для всех 18 предыдущих фич. Без него любой баг в новом коде приводит к тихому отказу. С ним — мгновенная обратная связь.

---

## 20. Онбординг: /start + нативный /help

**Проблема:** `/start` показывал 2 строки: "Claude Code Monitor. Каждый топик = сессия." Ни слова о 19 новых фичах. `/help` пересылался в Claude Code (бесполезно).

**Решение:** `/start` — краткий обзор возможностей (ввод, команды, фичи). `/help` — полный справочник: все команды, типы ввода, возможности. Нативный handler вместо пересылки в Claude Code.

**Почему это важно:** Без onboarding 90% фич не обнаруживаются. Пользователь не знает про reactions, document upload, forward context, input batching — пока не прочитает /help. А /help должен работать.
