# Функциональность CCBot

## Управление сессиями

### Создание сессии через directory browser

При первом сообщении в новый (непривязанный) топик бот показывает интерактивный браузер директорий. Пользователь выбирает каталог проекта, после чего создается tmux-окно с Claude Code. Топик привязывается к этому окну.

Браузер поддерживает:
- Пагинацию (6 директорий на страницу)
- Навигацию вверх (с ограничением `CCBOT_ALLOWED_ROOTS`)
- Скрытые директории (управляется `CCBOT_SHOW_HIDDEN_DIRS`)

Если в выбранной директории уже есть сессии Claude Code, бот предлагает session picker -- список существующих сессий с датами для возобновления через `--resume`.

Если в tmux уже есть свободные (не привязанные к топикам) окна, бот предлагает window picker -- привязку к существующему окну вместо создания нового.

### Возобновление сессий

При выборе существующей сессии через session picker бот создает окно с `claude --resume <session_id>`. Claude Code продолжает работу с сохраненным контекстом. При resume хук генерирует новый session_id, но бот отслеживает оригинальный JSONL-файл.

### Автоименование топиков

После первого текстового сообщения (кроме шаблонных вроде "привет", "hi", "ok") бот автоматически переименовывает топик по содержимому сообщения. Паттерны исключения: 15 вариантов приветствий и коротких фраз.

### Синхронизация имен

Переименование топика в Telegram автоматически переименовывает tmux-окно и обновляет display name в state.

### Закрытие и удаление

Закрытие или удаление топика автоматически:
1. Убивает связанный tmux-окно
2. Отвязывает thread binding
3. Очищает состояние (status messages, interactive UI, pending tools)

### Команда /kill

Завершает tmux-окно и удаляет топик. Отличие от ручного закрытия: `/kill` гарантированно выполняет обе операции.

### Команда /restart

Завершает текущее tmux-окно и создает новое в той же директории. Claude Code стартует с чистого листа. Топик сохраняется.

### Команда /unbind

Отвязывает топик от tmux-окна без завершения сессии. Окно продолжает работать, но сообщения из топика больше не маршрутизируются. Полезно для переподключения.

## Ввод

### Текстовые сообщения

Текст из Telegram пересылается в Claude Code через `tmux send_keys` в literal-режиме. Быстрые последовательные сообщения (интервал менее 1.5 секунды) группируются и отправляются одним блоком.

Ограничение длины: 4096 символов (совпадает с лимитом Telegram).

### Фотографии

Фото скачиваются через Telegram Bot API (выбирается наибольшее разрешение), сохраняются в `~/.ccbot/documents/` и путь к файлу передается Claude Code.

### Голосовые сообщения

Голос транскрибируется через Deepgram Nova-3 API (язык: русский), результат отправляется как текст. Требует `DEEPGRAM_API_KEY`. Без ключа голосовые сообщения игнорируются с уведомлением.

### Документы

Документы скачиваются и передаются Claude Code по пути к файлу. Whitelist расширений: стандартные текстовые и офисные форматы. Sensitive-имена файлов (.env, credentials и др.) блокируются.

### Правки сообщений

Отредактированное сообщение пересылается в Claude Code с пометкой "(Исправление)". Claude видит и оригинальный контекст, и исправление.

### Пересланные сообщения

Пересланные сообщения дополняются контекстом: "Forwarded from: Имя (username)". Claude получает информацию об авторе оригинала.

### Цитата-ответ

При ответе на сообщение бота цитируемый текст добавляется к запросу как контекст. Claude видит, к какому именно фрагменту относится вопрос.

### Реакции

Emoji-реакции на сообщения бота транслируются как короткий текстовый фидбек Claude. 19 маппингов:

### Проксирование команд Claude Code

Команды `/clear`, `/compact`, `/cost`, `/model`, `/memory` и любые другие `/команды` пересылаются напрямую в Claude Code через tmux.

## Вывод

### Чистый вывод (clean output)

По умолчанию включен (`CCBOT_CLEAN_OUTPUT=true`). Фильтрует:

- `tool_use` -- вызовы инструментов (Bash, Read, Grep, MCP и др.)
- `tool_result` -- результаты выполнения инструментов
- `thinking` -- внутренние рассуждения Claude
- `local_command` -- активации скиллов и хуков

Пропускает:

- Финальные текстовые ответы Claude
- Интерактивные запросы (AskUserQuestion, ExitPlanMode, Permission)
- Изображения из tool_result (скриншоты, сгенерированные картинки)
- Записанные файлы (автоотправка при Write)

При `CCBOT_CLEAN_OUTPUT=false` все сообщения доставляются в Telegram без фильтрации. Это может раскрыть секреты из Bash-результатов.

### Прогресс-статус

Пока Claude работает, бот показывает одно status-сообщение с описанием текущего действия (какой инструмент используется). Сообщение обновляется на месте через `edit_message_text`. При появлении content-сообщения status конвертируется в него, уменьшая количество сообщений в чате.

### Длинные ответы

Ответы длиннее 6000 символов (настраивается через `CCBOT_LONG_RESPONSE_THRESHOLD`):
1. Отправляются превью (начало текста) в чат
2. Полный текст записывается в `.md` файл
3. Файл отправляется как документ в тот же топик

### Автоотправка файлов

Когда Claude записывает файл через Write-инструмент, бот автоматически отправляет его в Telegram.

Whitelist расширений: `.md`, `.txt`, `.pdf`, `.docx`, `.doc`, `.xlsx`, `.xls`, `.csv`, `.html`, `.htm`, `.rtf`, `.epub`.

Защита:
- Двойная проверка `allowed_roots` (в мониторе и при отправке)
- Блокировка sensitive-имен (.env, credentials, id_rsa и др.)
- Исключение конфигурационного каталога (~/.ccbot/)
- Дедупликация по resolved-пути
- Лимит размера: >0 байт и <50 МБ

### Определение намерения отправки

Фразы типа "пришли в тг", "скинь в тг", "отправь в телеграм" (11 вариантов) автоматически добавляют hint для Claude: сохранить результат в файл, чтобы бот мог его отправить.

### MarkdownV2

Все текстовые сообщения конвертируются в Telegram MarkdownV2:
- Fenced code blocks
- Жирный, курсив, моноширинный
- Markdown-таблицы -> card-style формат
- Expandable blockquotes для thinking-контента

При ошибке конвертации -- автофолбэк на plain text.

### tool_use / tool_result pairing

Сообщение `tool_use` отправляется как отдельное сообщение. Когда приходит соответствующий `tool_result`, бот редактирует исходное сообщение, добавляя результат. Это сохраняет логическую связь и уменьшает количество сообщений.

### Message merge

Последовательные короткие content-сообщения автоматически склеиваются в одно (до 3800 символов). `tool_use` и `tool_result` разрывают цепочку merge.

## Мониторинг и диагностика

### /screenshot

Захват текста терминала tmux (с ANSI-кодами) и рендеринг в PNG. Отправляется с inline-клавиатурой для управления:
- Навигация: Up/Down/Left/Right
- Действия: Escape, Enter, Space, Tab, Ctrl+C
- Обновление скриншота

### /history

Пагинированная история сообщений сессии. Навигация через inline-кнопки (предыдущая/следующая страница). По умолчанию показывает последнюю страницу.

### /summary

Структурированный обзор сессии: список измененных файлов, выполненных команд и ключевых действий.

### /health

Диагностика бота:
- Uptime
- Количество активных сессий и привязок
- Состояние tmux-сессии
- Потребление памяти
- Наличие Deepgram API key

### /sessions

Список всех активных tmux-окон с:
- Именем окна (директория)
- Привязкой к топику (если есть)
- Индикатором работы Claude (pgrep)

### /usage

Отправляет `/usage` в Claude Code, захватывает модальное окно с информацией о расходе токенов и парсит результат.

### Idle reminder

Если Claude ожидает ввод более 120 секунд (настраиваемо), бот отправляет напоминание пользователю. Учитывает только время после последнего ответа Claude.

### Автоперезапуск

При обнаружении что Claude завершился (нет дочерних процессов у shell), бот:
1. Ждет grace period 5 секунд (защита от ложных срабатываний)
2. Пытается перезапустить с `--resume` (до 2 попыток, cooldown 60 секунд)
3. При неудаче -- убивает окно и уведомляет пользователя

### Детекция мертвых топиков

Каждые 60 секунд бот проверяет существование топиков через Telegram API. Если топик удален -- очистка привязки и tmux-окна.

### Startup-диагностика

При запуске бот проверяет:
- Наличие tmux-сессии
- Целостность state-файлов
- Наличие конфигурационной директории
- Доступность Deepgram (если ключ задан)

Результат отправляется разработчику (первый пользователь из `ALLOWED_USERS`).

## Interactive UI

### AskUserQuestion

Когда Claude задает вопрос, бот:
1. Захватывает текст терминала
2. Отправляет отформатированное сообщение с содержимым вопроса
3. Показывает клавиатуру управления

Следующее текстовое сообщение пользователя в этом топике передается как ответ.

### ExitPlanMode / Permission Prompt

При запросах на переключение режима или подтверждение разрешений бот показывает содержимое терминала с клавиатурой для навигации (стрелки, Enter, Escape и др.).

### Клавиатура управления

9 клавиш + Refresh:

| Клавиша | Описание |
|---------|----------|
| Space | Пробел |
| Up | Стрелка вверх |
| Tab | Табуляция |
| Left | Стрелка влево |
| Down | Стрелка вниз |
| Right | Стрелка вправо |
| Esc | Отмена |
| Refresh | Обновить скриншот |
| Enter | Подтверждение |

## WebSocket Bridge

### Возможности

WS bridge дублирует функциональность Telegram-бота для веб-фронтенда:

- Создание и возобновление сессий
- Отправка сообщений и клавиш
- Браузер директорий
- Загрузка файлов
- Получение истории
- Подписка на обновления (сообщения, статус, файлы, interactive UI)
- Периодический diff-capture терминала

### Протокол

26 типизированных сообщений (dataclass). Клиент отправляет:
- `auth` -- аутентификация
- `create_session` / `resume_session` -- управление сессиями
- `send_message` / `send_key` -- ввод
- `browse_directory` -- навигация
- `upload_file` -- загрузка файлов
- `get_history` / `get_sessions` -- запросы данных
- `subscribe` / `unsubscribe` -- подписки

Сервер отправляет:
- `assistant_message` / `status_update` -- контент и прогресс
- `file_message` -- файлы
- `interactive_ui` -- интерактивные запросы
- `terminal_update` -- diff терминала
- `session_list` / `history` -- данные по запросу
- `error` -- ошибки

## Безопасность

### Аутентификация

- Telegram: whitelist по user ID (`ALLOWED_USERS`). Каждый хэндлер проверяет `is_user_allowed()`
- WebSocket: token-based через `hmac.compare_digest`. Localhost bypass без токена для разработки

### Rate limiting

- Per-user: 30 сообщений / 60 секунд (все каналы: текст, фото, голос, команды)
- Глобальный: 30 запросов/с к Telegram API через `AIORateLimiter`
- WebSocket: 60 сообщений/мин на соединение
- Prefill bucket при рестарте для предотвращения burst

### Scrubbing

Чувствительные переменные удаляются из `os.environ` после загрузки. tmux session environment также очищается. Дочерние процессы не наследуют секреты.

### Ввод

- Null-байты и `\r` вырезаются из tmux send_keys
- UUID validation для session_id
- `shlex.quote()` для --resume команд
- Whitelist клавиш для WS send_key

## Ограничения и известные проблемы

### Архитектурные

- `bot.py` содержит около 3000 строк -- callback routing и обработчики команд не вынесены в отдельные модули
- Доступ к private API `AIORateLimiter` (`_base_limiter._level`) для prefill bucket -- может сломаться при обновлении `python-telegram-bot`
- `_ensure_formatted()` дублируется в `message_queue.py` и `message_sender.py`

### Функциональные

- Транскрипция голоса hardcoded на русский язык (`language: "ru"`)
- `DIRS_PER_PAGE = 6` в directory browser не конфигурируемо
- `/usage` зависит от формата TUI Claude Code и может перестать работать при обновлениях
- Status spinners в `terminal_parser.py` могут устареть при обновлении Claude Code

### Производительность

- `_msg_thread_map` может занимать память при высоком трафике (лимит 10 000 записей, очистка по TTL 14 дней)
- `find_window_by_name/id` вызывает `list_windows()` каждый раз (O(n) scan) -- не критично при малом количестве окон

### WebSocket Bridge

- Localhost bypass позволяет доступ без токена при `ws_host` in (`127.0.0.1`, `localhost`, `::1`) -- дизайнерское решение, потенциальная проблема в shared-hosting
- `/api/file` endpoint из `download_url` не реализован на стороне сервера -- URL формируется, но не обслуживается
